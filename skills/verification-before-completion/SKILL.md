# 完成前验证（证据先于断言）

**核心原则：证据先于断言，永远如此。** 违反字面规则就是违反规则本意。宣布"完成 / 修好 / 通过 / 没问题"之前，必须先拿出本轮**新鲜**的证据；没有证据的结论不是结论，是猜测——用"完成"的语气说出来就是欺骗。

## 何时用 / 何时不用

**必须用**：任何成功/完成声明；任何满意表达（"好了""完美""搞定"）；任何关于工作状态的正向陈述；提交、推送、建 PR 之前；转入下一个任务之前；委派子代理后收到"成功"汇报时。

**没有真正的例外。** 唯一不算违规的是**明确标注**这是未验证的中间态（"以下均未验证"）。草稿可以没有验收判据，但不能说它"能用"。

## 铁律与门禁

```
没有新鲜的验证证据，不得宣布完成。
```

"新鲜"= 本轮真的跑过、真的读过输出；上轮结果、别人汇报、记忆印象都不算。

门禁五步，缺一步就是撒谎而不是验证：**识别**（这条结论用什么证明？）→ **执行**（完整跑一遍，不跑片段）→ **读全**（读完输出、看退出码、数失败条数）→ **比对**（输出真的支持它吗？否就按实际说，是就带证据说）→ **然后才开口**。

## 流程

1. 把要说的话列成"结论清单"，用 `todo_write` 记住。说不清要说什么就别开始验证。
2. 每条结论配一个**可执行判据**（命令 + 期望输出 / 文件内容 / 真实调用结果：状态码、退出码、行数、字节数）。配不出判据的结论不许说出口。
3. 执行：命令用 `pwsh`；产物用 `read`、`glob`、`grep`、`read_image`；外部信息用 `web_fetch`；服务做真实调用。
4. 读**完整**输出：退出码、stdout、stderr、失败计数。"没报红"不算读到。
5. 比对：不支持 → 按实际报告；支持 → 逐条附证据（跑了什么、看到什么）。
6. **逐条跑验收判据**并打勾，而不是"整体感觉对了"。
7. **试失败路径**：坏输入、边界、空文件、不可达服务、越权路径。只跑 happy path 等于没验证。
8. 把未验证项**显式列出**，写明原因与影响。
9. 1–8 都做完，才说"完成"。

## 结论 → 需要什么证据

| 结论 | 需要 | 不充分 |
|---|---|---|
| 测试通过 | 测试输出：0 失败 | 上次结果、"应该能过" |
| 静态检查干净 | 检查器输出：0 错误 | 只查一部分、外推 |
| 构建成功 | 构建命令退出码 0 | 静态检查过了、日志好看 |
| bug 已修 | 复现原始症状的用例现在通过 | 改了代码就假定好了 |
| 回归测试有效 | 走完红→绿循环 | 碰巧通过一次 |
| 子代理完成 | 自己看到文件/差异真的变了 | 子代理说"成功了" |
| 需求满足 | 逐条对照计划打勾 | "测试都过了" |
| 文件已写入 | `read` 读回内容一致 | `write` 没报错 |

## 完成前清单（照做）

- [ ] 每条结论都有**本轮**跑出来的判据，不是记忆或推断；
- [ ] 产物**真的存在**：用 `read` / `glob` 打开确认内容，不凭"我刚写过"；
- [ ] 验收判据**逐条跑过**，并在结论里点名；
- [ ] **失败路径**试过，失败表现符合预期；
- [ ] 关键命令的**退出码**与**失败计数**实际读到；
- [ ] 子代理/后台任务的结论已独立复查，不采信自述；
- [ ] 未验证、未跑的项**逐条标出**，写明原因与风险；
- [ ] 结论写明"跑了什么、看到什么"，别人能复现同一结论。

## 本机最容易误判的三种"假通过"

**1. `pwsh` 返回 `0xC0000142`、零 stdout。** 这是执行器/沙箱故障，**既不是成功也不是判据失败**——它什么都没证明；当成"没报错 = 通过"是本机头号误判。对策：不反复重试同一条命令，改用 `read` / `glob` / `grep` 静态核验或请用户放行，并在报告里写明"该项未执行"。

**2. 通过 `http_proxy` 探测本机/局域网服务。** 设有代理时，`curl` 访问 `127.0.0.1` / `192.168.x.x` / `*.local` 会被代理截走，拿到**伪造的 502**（如 "502 upstream connect failed"）、401 或畸形响应，把正常服务判成故障；反向地也可能被兜底页骗成"服务正常"。对策：用 `curl.exe --noproxy '*'`（或 `-NoProxy`）直连，以**直连结果**为准；两者不一致时不用代理那次下结论。

**3. 写了文件但没读回来。** `workspace-write` 下工作区外路径会被沙箱拒绝、`write` 会失败；即便看起来"跑过了"也不能假设已落盘。对策：写完立刻用 `read` 读回比对，或 `glob` 确认存在——尤其工作区外路径、中文路径、覆盖写。

## 没验证完，就如实说

**发现没验证完，如实报告，而不是悄悄降低标准。** 不许把"我没测"改写成"应该没问题"，不许删掉没跑的清单项让表格好看，不许用"基本可用""大体完成"糊过去。诚实报告的代价是当下的尴尬，降低标准的代价是别人踩你埋的雷。

```
已验证：<结论> —— 证据：<跑了什么，看到什么>
未验证：<结论> —— 原因：<为什么没跑>；影响：<可能怎么坏>
阻塞：<需要谁放行 / 需要什么条件>
```

## 反模式 / 红旗（出现即停）

"应该可以了""大概没问题""看起来对了"；验证之前先表达满意（"太好了""完美""搞定"）；没验证就提交/推送/建 PR；直接采信子代理的成功汇报；部分验证当完整；"就这一次"；累了、想让活赶紧结束；**任何暗示成功但没跑过验证的措辞**。

## 完成判据

- [ ] 每条成功声明后都跟着本轮的实际证据；
- [ ] 产物用 `read` / `glob` 亲自确认存在且内容正确；
- [ ] 验收判据逐条跑过，无一项靠推断；
- [ ] 失败路径真的试过；
- [ ] 未验证项已被点名，而不是被省略；
- [ ] 没有"应该/大概/看起来"式的完成结论。

## 与其它技能的关系

`test-driven-development` 管**过程中**：每次改动先有会失败的测试（RED）再有 GREEN，自带证据；本技能管**结案**：把分散证据收拢成"可以宣布完成"的门禁。TDD 没做，本技能只能告诉你"没证据"，补不上。

`requesting-code-review` 管**对外**：交付前用评审换第三方视角；本技能管**对内**：宣布前先自我核验。顺序是先本技能、再 `requesting-code-review`。

委派 `subagent` / `subagent_fork` 时把本清单写进任务书，要求回报"跑了什么、看到什么"，收到后由你独立复跑关键判据；需求是否满足，回到 `writing-plans` 的计划逐条对照。

## 本机适配注意

- 一律用 `pwsh`（PowerShell 语法），没有 Bash。
- 常为 `workspace-write`：只有会话工作区可写，工作区外路径会被拒绝并打印 `[sandbox: file access denied ...]`——策略拒绝不是判据失败，也不要换写法绕。
- `pwsh` 的 `0xC0000142` 零输出是已知故障，见上文第 1 条。
- 工作区常不是 git 仓库：没有 diff 时用 `read` / `grep` / `glob` 直接核对产物内容作为等价证据，判据一条不减。
- 视觉产物用 `read_image` 读图确认，不只看到"文件已生成"。
- 技能真源在 `D:\Tools\skillshare\skills`，新技能落到真源再分发。
