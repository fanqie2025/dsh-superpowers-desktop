# 内联执行整份计划

按既有计划，由你本人逐项执行到底，末尾只做一次整体终审。

**为什么走这条路线。** 逐任务派子智能体的路线，为每个任务各付一次全新实现者和一次全新评审者的上下文；内联只付一份上下文（你的）加末尾一次评审。它放弃的是「每任务新鲜上下文」和「每任务第二双眼睛」，改用别的办法补回来：任务是规范、台账是记忆、每项立刻校验是门禁、终审是第二双眼睛。

## 何时用 / 何时不用

**用本技能，当：**

- 已有一份 `writing-plans` 产出的计划，人类伙伴在交接时选了内联执行。
- **取舍**：任务耦合紧（后面的任务要消费前面刚定的接口／配置／命令名）、需要连续上下文才做得对、总改动面小 → 内联更划算。
- 这次没有可用的子智能体（不要伪造一次派发，就在这里把计划跑完）。

**改用 `subagent-driven-development`，当：**

- 任务之间基本独立、可以并行推进。
- 伙伴要求**每个任务都过一道评审门禁**，而不是末尾一道。
- 计划长到后半段会跑在压缩过的上下文里——内联也能跑完（台账让它可恢复），但最后几个任务拿到的「你」最少。

## 核心原则

- **计划已经做过思考。** 精确执行它，每一项都用你亲眼看过「先失败、后通过」的证据证明，并留下能扛住自己遗忘的记录。
- **台账是记录，todo 是视图。** `todo_write` 给人看进度，`progress.md` 给压缩后的你看进度。恢复时以台账和产物为准，不要信自己的回忆。
- **连续执行。** 任务之间不要停下来问「要不要继续」。只有四件事能停你：不可逆或破坏性操作；安全敏感动作；本工作区之外的副作用（合并、推送共享分支、发布）；计划烂到每条路都是猜。这四种用 `ask_user_question` 问。
- **裁定，而不是停摆。** 规范是约束性权威，计划是它的论证，判不下来时按「满足规范的最小改动」定。每条裁定写进台账：`裁定: 决定了什么 — 为什么 — 错了要付什么代价`。**不落台账的偏离，等于偷偷做的决定。**
- 工具调用之间最多一句短话，记录由台账和工具输出承担。

## 流程

**1. 准备。** 确认工作在隔离环境里（是 git 仓库就用独立分支／worktree；不是就限定在计划所属目录内），绝不在 main/master 上直接动手。读一遍计划，记下上下文与全局约束；计划引用了规范就一并读——冲突以规范为准。用 `todo_write` 为每个任务建一项，第一项置 `in_progress`。**预检**：扫描任务间的共享接口，凡「后面的任务消费前面的产物」写一行台账；没有就写 `预检: 无共享接口`。

**2. 工作区与台账。** 每份计划拥有一个工作区，存放台账与长输出，与 `subagent-driven-development` 同目录、同格式，便于中途换执笔人。台账首行写明身份：`# 执行台账 — 计划: <计划文件路径>`。台账里已有 `任务 <N>: 完成` 行的任务就是**已完成**，产物已经存在，不要重做。首行指向别份计划的台账别动它，自己新建一份。

**3. 取任务。** 读该任务的原文（记忆只是摘要，原文才有确切的值、签名与验收命令），把它的 todo 置 `in_progress`。

**4. 按步执行。** 逐步来，**每步做完立刻校验，不要攒到最后**：跑该步的命令 → 读真实输出 → 对照该步写明的 `Expected`。三种结果：**符合** → 下一步；**实现错了** → 停下查根因，不要为了让输出对上而改症状；**计划错了**（与规范矛盾、接口对不上、命令跑不通）→ **停下改计划**，按规范取最小改动，写 `任务 <N>: 裁定: …` 进台账，再继续。裁定带在台账上，不靠记忆。

**5. 收尾本任务。** 写完成行之前必须同时成立，证据就在本次会话里（不是「diff 看起来对」）：任务点名的每一项验收都真跑过、且你读过输出；任务级最终校验命令跑过并通过（它是判据，不是「每步都过了」的替代品）；每条 `Expected` 都对照过真实输出；每处偏离都有 `裁定:` 行。缺一条就不算完成。**运维类计划项的验收判据要写成「可观察的输出／真实的调用结果」**——真实接口的返回、真实端口的连通性、日志里的那一行、文件确实存在及其内容；不接受「应该没问题」。**若 `pwsh` 返回 `0xC0000142` 且零输出**，改用文件工具继续，并在台账把该步标 `未验证`——**标未验证不算通过**，也不要反复重试同一条命令。

**6. 前进。** 完成行写进台账（任务号、产物指向、校验命令 → 结果；是 git 仓库再加提交范围），同一批动作里把 todo 标 `completed`，然后取下一条任务。

**7. 全部任务完成后做整体终审**（见下节），终审干净且修复已落地再收尾（清理本计划的工作区）。

## 整体终审

终审是**一次单独的、覆盖整体的**评审，**不是把每步自检加起来**：每步自检只证明「这一步如计划所愿」，终审要回答「整份计划的目标达成了吗、有没有计划本身没覆盖的破坏」。

判据清单（逐条对照，缺一条终审就不算做完）：

- 计划的全局约束与验收章节**逐条**对照，每条给出证据来源。
- 最后完整跑一次任务级校验／测试命令，读完整输出（不是只看尾巴的某一段）。
- 每项判据都指向**可观察的输出或真实的调用结果**，运维动作确实执行过，不是推断。
- 所有 `裁定:` 行重读一遍：是否仍然自洽、彼此是否冲突、哪些必须写进回报让人知道。
- 有没有计划之外被改动的东西（越界修改、顺手的「优化」）。
- 有没有因本机执行故障被标成 `未验证` 的步骤——列清楚，它们是未结清的风险。

**有子智能体时**：用 `subagent` 把整体评审派出去，尽量指定最强模型（整体评审是判断类工作），给它计划、规范和台账里的 `裁定:` 行。**这是整轮唯一买到的全新上下文，不要跳过，也不要用「我自己看一遍 diff」顶替。** 没有子智能体时：在最后一条完成行之后，作为**单独一遍**按上面清单自查，台账写 `终审: 自查（无子智能体工具）`，回报里说明「作者自查弱于独立评审，是否足够由你决定」。

**处理结论**：按影响重新定级（标签可能评的是「规范没说」，你要评的是「用的人会得到什么」）。**严重与重要**进入**一次**修复：每个修复先写出能复现该问题的验证并看它失败，改到通过，再跑全量并保持全绿；修复由你本人做，不再派二轮评审。**次要**只写进台账 `终审: 次要（暂缓）: <一句话>` 和回报里的「暂缓的次要项」，**不进修复轮，也不写成裁定**。决定不修的发现要写成 `终审: 裁定: …`。

## 反模式（会怎么错）

| 借口 | 现实 |
| --- | --- |
| 「我记得任务 N 写的是什么」 | 你记得的是摘要；原文才有确切的值，去读它。 |
| 「计划里的代码是对的，跳过看它失败」 | 没看它失败过的验证证明不了任何东西。那只是一步，去跑。 |
| 「每步跑太碎，最后跑一次全量就行」 | 逐步跑才知道是哪一步弄坏的；任务末的全量是契约，不是替代品。 |
| 「计划这里不对，我直接做对的事」 | 做对的事，同时把裁定写进台账；不落台账的偏离是偷偷做的决定。 |
| 「台账等做完几个任务再补」 | 上下文压缩不挑方便的时刻。一个任务一行，和产物同一批写。 |
| 「先问一下要不要继续下一个任务」 | 人选内联执行就是为了少花钱。只有那四种情况能停你。 |
| 「我自己看 diff 很仔细，终审多余」 | 同一个作者，同一个盲区。终审是整轮唯一的新鲜上下文。 |
| 「改动很小，验证应该会过」 | 「应该」不是证据；契约要的是命令和它的输出。 |

## 完成判据

- 台账里每个任务恰有一条完成行，行内含校验命令与结果。
- 每一步的 `Expected` 都有对照记录，所有偏离都有 `裁定:` 行。
- 整体终审按上面的清单完整做过一遍，结论写在台账；未结清项（含 `未验证`）在回报里逐条列出。
- 回报必须包含**我做的裁定**（按时间顺序，每条附「错了要付什么代价」）与**暂缓的次要项**，两份清单都要穷尽——这是伙伴唯一能看到你替他做的决定的地方。

## 与其它技能的关系

- 上游：`writing-plans` 产出计划 → 交接时在本技能与 `subagent-driven-development` 之间选一条。
- 全程受 `test-driven-development` 约束（计划的步骤顺序就是先红后绿）；宣称完成前受 `verification-before-completion` 约束；实现出错用 `systematic-debugging`。
- 终审参考 `requesting-code-review`；收尾用 `finishing-a-development-branch`；需跨会话追踪可用 `create_goal`。

## 本机适配注意

- 宿主是 DeepSeek Harness 桌面端（Electron），Windows；文件策略常为 `workspace-write`，只有会话工作区可写。计划要改工作区之外的路径就会撞沙箱——那是要停下来问的情形，不要绕。
- **工作目录通常不是 git 仓库**，也常常没有测试套件。上面涉及 worktree、分支、提交、测试套件的步骤都是**条件式**：是 git 仓库就按提交与范围记账；否则退化为「改动文件清单 + 命令与其真实输出」，判据等价（有命令、有输出、有结论）。
- 上游随附的 `scripts/`（工作区解析、取任务、完成任务、评审打包）在本仓库**不移植**：用 `read`／`write`／`edit`／`glob`／`grep` 加 `pwsh` 手工完成等价动作，判据不变。
- 沙箱明确拒绝会打印 `[sandbox: file access denied ...]`；`0xC0000142` 是另一种形态。
- 访问 `127.0.0.1`／局域网服务时，本机 `http_proxy` 会伪造 502，用 `curl.exe --noproxy '*'` 或 `-NoProxy`。
